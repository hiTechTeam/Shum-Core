# Установка и распространение CLI

Обычная установка должна использовать готовые бинарники. Пользователь выбирает
установщик или пакетный менеджер. Сборка из исходников остаётся отдельным способом
для разработчиков.

## macOS

`scripts/package_macos.py` создаёт:

* установщик `.pkg`, который кладёт `shum` в `/usr/local/bin`;
* архив с бинарником для Homebrew;
* формулу `dist/homebrew-shum/Formula/shum.rb`;
* SHA-256 и JSON с версией, архитектурой и минимальной macOS.

Пакет не меняет `.zshrc`, профили или переписку. В нём нет установочных скриптов.
После установки достаточно открыть терминал и выполнить `shum`.
Если раньше использовалась установка через Cargo, `command -v shum` может показывать
старую копию из `~/.cargo/bin`. Установщик не удаляет её автоматически.

Сборка на Mac:

```sh
python3 scripts/package_macos.py
```

Или упаковка уже проверенного бинарника:

```sh
python3 scripts/package_macos.py --binary ~/.cargo/bin/shum
```

Скрипт проверяет архитектуру, версию и динамические зависимости. Требование к версии
macOS учитывает как CLI, так и встроенную службу Bluetooth. У текущего проверенного
бинарника Apple Silicon нижняя граница macOS 15.0. Проверка на более старой системе
не проводилась. Пакеты Intel, Windows и Linux в этой работе не собраны.

Проверка пакета без установки:

```sh
python3 scripts/verify_macos_package.py dist/Shum-CLI-0.1.0-macOS-arm64-unsigned.pkg
```

## Homebrew

Формула устанавливает готовый бинарник, проверяет SHA-256 и предоставляет тест версии.
Для локальной проверки она ссылается на `file://` архив из `dist`.
Для распространения скрипту нужно передать `--release-base-url` с HTTPS-адресом
каталога опубликованных артефактов. Формулу следует публиковать в tap
`hiTechTeam/homebrew-shum`. После публикации предполагаются команды:

```sh
brew install hitechteam/shum/shum
brew upgrade shum
```

Публичного tap и загруженных артефактов пока нет. Команда из макета сайта показывает
целевой способ установки, а не уже опубликованный пакет.

## Остальные менеджеры

В макете загрузок предусмотрены winget для Windows, apt для Debian/Ubuntu и dnf для
Fedora. Для фактической поддержки нужны проверенные бинарники соответствующих ОС,
пакеты и публикация в каталогах или репозиториях. Эти способы пока не реализованы.
Наличие карточки в Figma не означает доступность пакета.

## Публичный выпуск

Локальный `.pkg` без сертификата помечается `-unsigned`.
Для публичного распространения нужны подпись бинарников Developer ID Application,
подпись установщика Developer ID Installer и нотарификация Apple. Опция
`--sign-installer` подписывает только контейнер установщика и сама по себе не
нотарифицирует выпуск. Автоматическое получение сертификатов и отправка в Apple
не выполняются.

Скрипт ничего не публикует и не включает CI. Архивы `dist` исключены из Git.
