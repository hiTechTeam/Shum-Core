# Хранилище и профили

`shum-store` открывает SQLite iOS v1 без преобразования: таблица `records`,
HMAC-индексы, BE16 ID, AAD и CryptoKit ChaChaPoly combined по spec/09.
SQLite поставляется через bundled `rusqlite`; системная версия SQLite
не определяет формат. JSON хранения допускает дробные Swift Date и
сохраняет неизвестные поля. Сетевой canonical JSON здесь не применяется.

Чтение проверяет каждую строку, counts, ID, positions и общий лимит 100 MB.
Ошибка не возвращает частичную историю. Изменение состояния выполняется
через `Store::transaction` или `commit`: сначала durable `BEGIN IMMEDIATE`
с `synchronous=FULL`, затем обновление памяти. ACK и другие действия ядра
клиент выполняет только после успешного commit. Ошибка SQLite оставляет
память прежней. Одинаковое состояние не создаёт транзакцию; неизменённые
строки сохраняют nonce. Удаление сохраняет позиции соседей; перестановка
перенумеровывает массив.

`Store` удерживает межпроцессную блокировку `<database>.lock` до закрытия.
`PRAGMA data_version` дополнительно обнаруживает запись сторонним SQLite
соединением. Тогда нужно закрыть базу и загрузить состояние заново.
В этапе 4 daemon станет владельцем профиля, команды будут обращаться
к нему через локальный IPC. Пока IPC не реализован.

Создание и миграция старого ChaChaPoly snapshot используют временную
базу в том же каталоге, checkpoint, fsync и атомарный rename. Исходный
snapshot сохраняется как `.v1-recovery`. `portable_snapshot` возвращает
зашифрованный полный JSON, совместимый с iOS backup. Старый AES-GCM архив
Bitchat импортируется отдельно через `import_legacy_archive` с явно
переданным legacy key. Storage key вместо legacy key не используется.
Криптографический импорт не меняет исходный файл.

## Ключи

Четыре независимых ключа по 32 байта: X25519, Ed25519, secp256k1 и storage.
Их создаёт системный CSPRNG адаптера. `shum-core` не обращается к ОС.
Секреты не реализуют Debug/Serialize; принадлежащие нам временные буферы
очищаются через zeroize. Это не гарантия очистки копий внутри SQLite,
драйверов и системного хранилища.

`keyring` 3.6 использует Keychain на macOS/iOS, Credential Manager на Windows
и Secret Service на Linux. Включены соответствующие target features;
подмена системного backend на mock не используется.
[Документация keyring](https://docs.rs/keyring/3.6.3/keyring/).

На Linux без `DBUS_SESSION_BUS_ADDRESS` Auto выбирает файловый режим.
Явный `KeyMode::File` также разрешён на Unix. Файл `keys.bin` имеет права
0600, каталог профилей 0700. Чтение отказывается от symlink и файла с
расширенными правами. Формат: `SHUMKEY1` и четыре raw key в указанном
порядке, без JSON и вывода секретов в журнал. Файловый режим на Windows
отклоняется, там требуется системное хранилище.

Ошибка доступа, блокировка или исчезновение ранее созданного Keychain
не вызывает смену backend либо генерацию новых ключей. Backend записан
в реестре профиля. Режим файла защищает доступом ОС, сам файл не зашифрован.

## Профили

`Profiles::new` принимает явный выделенный каталог. В нём `profiles.json`
хранит ID, локальные имена, ownerID, выбранный профиль и backend; секретов
в нём нет. Каждый случайный ID имеет отдельный каталог, ключи и SQLite.
Реестр обновляется атомарно под кратковременной межпроцессной блокировкой.
Открытые базы разных профилей работают независимо. Удаление открытого
профиля отказывается с `Locked`. Удаление сохраняет tombstone в реестре,
поэтому прерванную операцию можно повторить. Удаление не обещает физического
стирания SSD или внешних резервных копий.

## Проверка

```sh
cargo test -p shum-store --locked
cargo test -p shum-store --locked --test profiles native_keyring_roundtrip -- --ignored --exact
cargo run -p shum-store --example storage_roundtrip -- ../Shum-Protocol/vectors/09-rust-roundtrip.json
```

Вторая команда обращается к настоящему системному хранилищу, создаёт только
временный тестовый профиль и удаляет его. Она исключена из обычного CI,
который может не иметь открытого пользовательского Keychain.

Проверено на macOS: исходная база Swift читается Rust, все 14 encrypted
records воспроизводятся побайтово; Swift читает изменённую Rust базу и
переносимый snapshot. Проверены дробные/отрицательные Date, no-op,
сохранение nonce, перестановки/удаления, отказ по повреждению, rollback,
конфликт writers, два профиля, права файлов и настоящий Keychain.
Проверка Secret Service и Credential Manager на Linux/Windows ещё не
выполнена. Облачный CI остаётся отключённым по просьбе владельца.
